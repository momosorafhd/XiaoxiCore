# 在一台 Linux 机器运行小希助手

小希 Core 提供主人管理台、助手、图书馆和两个适配器。先启动 Core 就能登录管理台、编辑角色和查看图书馆。要收发真实私聊，再把自己管理的 DSH（模型与会话宿主）和 SnowLuma（QQ 渠道）接到 Core。以下按同机、同一网络命名空间部署，支持范围为 Linux。

## 第一次登录

准备 Python 3.12 或更新版本，在含有 `run.py` 和 `platform.example.json` 的源码目录执行。用普通用户运行，`platform.local.json` 与样例放在一起，这样相对路径 `plugins` 能找到随包插件。

```sh
umask 077
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-platform.lock
cp -n platform.example.json platform.local.json
data_dir="${XDG_DATA_HOME:-$HOME/.local/share}/xiaoxi-core"
.venv/bin/python -c 'import getpass; print(getpass.getpass("主人密码（至少 14 个字符）: "))' |
  .venv/bin/python run.py platform --config platform.local.json --data "$data_dir" --init-password-stdin
.venv/bin/python run.py platform --config platform.local.json --data "$data_dir"
```

在这台机器的浏览器打开 `http://127.0.0.1:18910`，使用刚设置的密码登录。第二次启动只需运行最后一条命令，并沿用同一数据目录。默认只监听本机，外部门户列表为空，QQ 桥处于离线状态。密码、对话、记忆和角色编辑保存在本实例的数据目录。

## 接入自己的 DSH

DSH 的安装、模型账号、服务启停和 profile（启动配置）由部署者管理。已验证的宿主组合为 Linux、Node 24、DSH `0.2.2-rc.2`。Core 使用两端组件：Python 插件 `plugins/dsh_bridge` 向 DSH 提交会话，DSH 加载项目自带的 `packages/xixi-bridge/src/existing-dsh-plugin.mjs`，并从相邻的 JavaScript 文件加载工具与提示逻辑。请保留插件目录结构。

先为当前 Linux 用户生成独立私有配置。下面的脚本要求一个尚未创建的目录，并在仓库外生成三个文件。它只输出文件名，已有目录会被保留。若目录已存在，请沿用原文件。将 DSH 的 profile 指向生成的 `bridge.json`，把 `onebot.token` 的值通过部署者自己的安全配置途径填入 SnowLuma。

```sh
secret_dir="${XDG_CONFIG_HOME:-$HOME/.config}/xiaoxi-core/private"
.venv/bin/python scripts/init_bridge_secrets.py "$secret_dir"
set -a
. "$secret_dir/core.env"
set +a
```

生成的环境只对当前 shell 及其后续子进程生效。停止前一节临时启动的 Core，在同一终端使用同一条启动命令重新运行。若使用服务管理器，给 Core 指定相同的私有环境文件。

在自己的 DSH profile 增加插件条目。将两个示例路径换成绝对路径。

```yaml
- insert:
    - id: xixi-platform-dsh-bridge
      name: file:///absolute/path/to/packages/xixi-bridge/src/existing-dsh-plugin.mjs
      config:
        configFile: /absolute/private/path/bridge.json
```

将 YAML 中的 `file://` 路径指向检出的插件绝对路径（如有空格，用 URI 编码）。`configFile` 填上面生成的私有 JSON 绝对路径，由 DSH 运行账号读取，权限为 `0600`。如果修改端口，`bridge.json` 的 `coreUrl` 要对应 Core 回调地址，`port` 要对应下例 Core 侧桥 URL。`root` 是桥账本，`cwd` 是助手工作目录。两者均应属于该实例。模型密钥保存在 DSH。

加载 DSH 插件后，在 Core 的「模块管理 → DSH 桥 → 配置」保存下列设置，再启用模块。如果给已经运行的 Core 增加令牌环境变量，需重新启动 Core 进程。DSH 插件提供的健康接口会被 Core 在启用时核对。

```json
{"mode":"dsh","url":"http://127.0.0.1:18766","tokenEnv":"XIXI_DSH_BRIDGE_TOKEN"}
```

「模型设置」可以从自己的 DSH 模型目录选择日常、工作和整理模型。「原生提示」中的部分高级覆盖需要与宿主版本匹配的渲染补丁；普通工具桥与这些补丁分开加载。

## 接入 QQ 和主人白名单

在「模块管理 → 主人私聊消息桥 → 配置」填写以下字段，再选择反向连接模式。这是单主人助手。一个实例共用一套日常会话、角色和记忆；交给另一位主人时，给对方新建 Core 数据目录和 DSH 桥账本。

| 字段 | 同机配置 |
| --- | --- |
| 主人 QQ（`ownerId`） | 唯一允许的私聊发送者，也是补收和回复的对象。填写自己的 QQ 号。 |
| 机器人 QQ（`botId`） | SnowLuma 实际登录的机器人账号，与主人 QQ 分开填写。 |
| 监听地址、监听端口 | 地址填 `127.0.0.1`，端口选一个空闲的非特权端口，如 `18912`。 |
| 允许连接的客户端 IP（`allowedPeerIp`） | 同机原生进程填 `127.0.0.1`。容器部署须按实际网络设置可达的私网监听地址与来源 IP。 |
| 反向连接令牌文件（`reverseTokenFile`） | 填 Core 可读的私有文件绝对路径。文件内容是单独生成的 32 到 4096 个可打印非空格 ASCII 字符。将同一令牌配置在 SnowLuma。 |
| 消息索引（`historyIndex`，可选） | 指向本账号、该 SnowLuma 实例的消息索引 SQLite 文件，用于跨页补收时核对锚点。 |

保存并重载消息桥。在自己的 SnowLuma 配置一个 OneBot 反向 WebSocket 客户端，角色用 `Universal`，地址按上例为 `ws://127.0.0.1:18912/xixi-onebot`。连接后，Core 会核对机器人账号。在「模块管理」启用「小希助手」，再去「助手运行」启动收件。普通私聊的链路如下。

```text
主人 QQ → SnowLuma → Core 核对白名单 → DSH 插件调用模型
        ← SnowLuma ← Core 核对原收件人 ← 模型回复
```

验收时先用主人账号发一条私聊，再用另一账号发送，确认只有主人收到回复。保持手机在线，停止助手收件、发一条主人消息、重启收件，核对该消息编号只接纳一次。补收按助手的接纳记录去重。若首批 200 条未覆盖停机时间且无法核对服务器分页锚点，界面会报告覆盖不完整。

## 选配局域网

只在本机使用时，前述配置已经足够。要从其他设备登录，先为自己的局域网地址准备 HTTPS 反向代理，再在运行配置中设置 `http.origin`（浏览器实际访问的完整来源）、`trusted_proxy`（反向代理地址）和 `allowed_networks`（允许访问的本机及私网网段）。Core 仍监听回环地址，由代理覆盖 `Host`、`X-Forwarded-Proto` 和单个 `X-Forwarded-For`。代理对外屏蔽 `/_gateway-auth`、`/_qq-owner-auth` 及机器回调前缀 `/api/bridge/`。

首页和侧栏的快捷入口由「模块管理 → 管理台 → 配置」的 `serviceLinks` 决定。例如下列设置添加一个本机 DSH 网页入口。保存后重启 Core 生效。局域网用户应填写浏览器所在设备可访问的地址。添加快捷入口只会增加链接，跨服务统一登录需单独配置网关。

```json
{"serviceLinks":[{"label":"DSH","url":"http://127.0.0.1:3080/","description":"会话与模型"}]}
```
